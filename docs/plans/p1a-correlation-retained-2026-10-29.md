## 根因及最小修改

10k 行、50 参数、24 图的真实缓存更新回调复现为 419.45ms，未通过新增的本轮渲染回调 `<300ms` 验收。原有性能门槛未修改。随后 profile 显示：465ms 渲染回调中约 399ms 在原生散点的 `setData/addPoints`，其中大量时间用于为同一种符号逐点生成样式记录、矩形，再写回缓存。坐标轴/标题和 autoRange 是次要成本。

生产增量只有两个文件：

- `metrology_app/correlation_page.py`：来源型散点显式传入 `broadcast_uniform_symbols=True`，包括 WKB 的 Reference、Raw 和交叉来源。已有分批创建、版本取消、缓存、网格复用、Swap 和导出逻辑不变。
- `metrology_app/plotting/curve.py`：给现有 `ResponsivePlotDataItem` 增加默认关闭的符号样式适配。只有四个样式字段都使用全局默认值、没有悬停样式、没有额外 scale 时，才枚举一份样式。原生 `ScatterPlotItem.updateSpots` 用 NumPy 广播该矩形到全部点。混合/逐点/悬停/缩放样式继续调用原生完整枚举；点数组、元数据、命中检测、边界、失效通知、atlas 重建和绘制仍由原生类处理。适配器只持有散点的弱引用。

显式启用时，先建立空 PlotDataItem，安装适配器，再通过原生 `setData` 装入完整数据，避免首绘先重复生成全部相同符号。默认分支仍按原顺序初始化，Trend 等现有调用未启用该选项。

没有修改 OLS、拟合筛选/排序、Matplotlib 模型、数据归属、Undo、Workbook 更新架构或持久化协议。没有减少数据点或拟合，也没有按焦点/tab 跳过刷新。仍保留上一轮每批两个新面板、旧画面完整保留和最终整体发布。

## 内存和关闭后的资源

不截图、不强制 GC 的三轮主基准，进程累计 Peak Working Set 旧 600.33MiB，新 695.81MiB，临时峰值实测增加约 95.48MiB；不能声称内存优化。首轮创建 Private Bytes 增量旧 44.48MiB、新 42.66MiB，但后续关闭对象的回收时机使新版本三轮峰值较高。

另做成对的关闭后诊断：所有计时已结束、Qt 对象已销毁，才清理基准自身的强引用并显式 GC。每轮旧、新 Qt widget 数均回到 0；新版本后两轮可回收约 25,148 个 Python 对象，释放约 66.23/67.69MiB Private Bytes，回收后 Private Bytes 为 1514.64/1513.70MiB。旧版对应约 1526MiB。该证据支持关闭后对象等待 GC，而非本次观察到的不可回收增长；三轮仍不足以排除长期泄漏。

生产路径没有添加 `gc.collect`、没有禁用 GC，也没有把诊断回收时间移出正常操作以伪造主结果。主性能和峰值表仍采用无强制 GC 的实测。临时峰值提高应保留为 P1 后续资源专项的交接项。
