# Correlation 300ms：数据版本方案与实施记录

2026-10-28。批量事务方案已经实施；本文件的数据归属改动也已获用户单独批准，正在分步实施。
不修改 WKB/Recovery 文件格式，不开始目录重构，不推送或发布。

## 用直白的话说

目前一次粘贴要让表格、Workbook 分析、子表、相关计算分别准备自己的完整数据。
已完成的优化减少了其中的逐格记账和图布局重建，但仍要重复搬运、比较很多数据。

下一步建议让一次改动只生成一个**不可变数据版本**。各分析读取这个版本；再次编辑
生成新版本。需要独立编辑的子窗口获得自己的版本，继续保留草稿归属与精确基线检查。
图仍随数据刷新，不依赖焦点或当前 Tab。完成时间仍包括数据、拟合和当前图的更新。

## 为什么需要单独提出

现有 10k 行、50 参数表格层粘贴中位数仍约 765ms，单这一层已经超过总预算。
50 参数完整刷新单次测量仍约 V=4.15s、Z=3.13s；只改一列并停在 Data Tab 约
V=2.47s、Z=2.10s。这些是当前实际断点，不是本方案的性能承诺。

本阶段新增范围会改变 `SheetModel.cells` 的内部存储和主/子窗口读取数据的归属。
它超出已批准的“命令按列记账、严格回退子表增量提交”。用户此前明确要求数据所有权、
Undo 事务及异步发布等高风险修改先提供方案与风险，所以不能直接扩大实施范围。

## 分步边界

1. 先新增可独立测试的列式表数据版本。源字符串、表头、记录行标记与位置全部保留。
   不把字符串强制变成浮点。已有 `cells` 的读写、copy、快照、普通 Undo 和投影接口
   保持兼容；未知/直接 mutation 必须使快路径失效，不能只依赖 revision 猜测。
2. 只替换严格同结构批量数值路径。新列由新版本独占；未变列只能共享不可变存储。
   DataFrame 公共读取仍返回可独立修改的副本；内部分析通过明确只读入口读取。
   一次编辑仍是一次 Undo，所有必要通知与回调即时读数保留。
3. 父/子使用同一来源版本准备分析，减少同一事务的重复完整复制、识别和比较。
   独立草稿、手动 Ref、Card、Group、Mapping、参与选择与基线接受仍沿用原语义。
   结构、空白、身份、锁定及未知上下文全部保留原路径。
4. Correlation 在上下文与原行配对被证明不变时复用未受影响的参数对；全部参数变化
   时研究共同有效行上的批量矩阵 OLS。缺失值/病态输入继续原安全回退，保留现有
   数值误差检查、坐标方向、颜色、单位、拟合排序和过滤规则。
5. 只有数据阶段证明有效后，再处理散点的重复样式准备。所有原始点和绘图风格保留，
   不抽样、不移除点、不通过把图片等到聚焦时才更新换取计时成绩。

每一步单独 profiling、红回归、最小改动、专项回归、相同输入前后对照；不能同时
替换模型、Undo、发布机制和渲染器。某一步没有收益就不保留其额外复杂度。

## 必须锁住的风险

- 源字符串与精度、重复/前导零标签、空白记录、原行映射和参与状态不能改变。
- 旧版本和旧公共快照不可随新编辑改变；不共享新增可变帧或数组。
- 普通编辑与批量编辑交错、快速 V/Z/Y、嵌套回调和未知 changed.emit 都必须正确。
- 保存/Recovery/导出只接受完整且当前的版本，不得捕获半提交状态。
- 旧后台结果、取消、关闭、重新打开与人工子表编辑必须继续拒绝错误覆盖。
- 只允许有界的计算缓存；不减少 Undo 历史，不用 RSS 波动直接判泄漏。

## 验收、停止与回滚

固定保留 10k 行 ×50 个已绘制参数、全部 100 wafers、1225 个参数对的密集更新；
另测只改一列、非聚焦 Raw 浮窗和 Data Tab 场景。不能用后者替代前者。
记录冷/热、完整耗时、按键阻塞、Qt 停顿、全部断言与重复样本；300ms 门槛不变。
首次导入、结构变化和 100k×33 分开记录，不伪装为正常热更新的成功。

沿用既有框架，先专项、源码稳定后一次完整隔离回归；原设置/原 WKB 哈希保护。
每个有效步骤保存独立本地 checkpoint，回滚只撤销本步骤源/测试，不 reset 用户工作。
若达不到 300ms，报告剩余热点和真实数据，不提前宣布成功。
本方案没有未经测量的耗时保证。完成本阶段后停止，不自动进入 P1/P2/P3 或发布。

## 已批准阶段，第 1 步

从 `e9a19be` 开始，新增纯 `LiteralTableVersion` 与兼容单元格 Mapping；仅已跟踪、
同结构、密集字符串批量路径采用版本交换。一般编辑、空白、结构变化与子类保留字典路径。
直接写入公开 `cells` 会丢弃版本/缓存；Undo 仅在当前版本对象与命令期望对象相同时交换，
否则回退逐项应用，保留命令之外的外部编辑。公共 DataFrame 和快照继续独立可改。
没有修改持久化格式，也没有接入按焦点延迟刷图。

红测试：`tests.test_sheet_versions` 在接入前失败，揭露直接 mutation 读取旧缓存及没有版本交换。
接入后纯数据/表格合同 22/22、批量加载/选择/Workbook Copy 集成 44/44 通过。
证据目录为既有 QA 下的 `raw-click-20261027/data-version/`。

同机同 10k×50、3 轮表格层（含真实剪贴板文本解析、两类信号观察者独立读帧）P50：

| 操作 | 本轮接入前 | 第 1 步（含批量校验循环优化） |
| --- | ---: | ---: |
| Paste | 712.27ms | 511.01ms |
| Undo | 280.98ms | 64.30ms |
| Redo | 301.33ms | 110.31ms |

这是表格层局部结果，**不是完整 Correlation 延迟，Paste 也仍未达 300ms**。
本步尚待其余数据安全专项及原生整体对照，不能据此宣布任务完成或全量全绿。

## 第 2 步：子表接收不可变来源

父模型已有不可变版本时，将其随原请求传给现有后台准备流程。后台逐列核实来源帧的
字面值、位置、表头与元数据都与版本相同，才复用该版本；否则原完整准备路径不变。
子窗口仍创建自己的可变 DataFrame；其编辑、草稿判定、旧结果拒绝、取消和发布流程不变。

`tests.test_linked_table_versions` 接入前先失败；接入后与既有数据/子表/主图专项合计 29/29 通过。
同机 10k×50、5 轮交替对照，子表准备及加载（含通知时独立读帧）P50 从 315.41ms 降为
71.42ms。该局部对照不包含分析/绘图。原生全部 1225 对和当前图验收通过，300ms 门槛仍失败。
同一原生输入各单次完整 V/Z/Y 从 3761.54/2899.77/3240.73ms 变为
3298.52/2426.32/2983.67ms；单样本不能作为 P50/P95 或稳定整链提速承诺。

补充 10k×30 表格层 3 轮：旧 Sheet 实现覆盖、当前批量校验共同使用时，V/Z/Y P50 为
335.29/148.08/156.09ms；当前版本为 356.08/41.46/67.67ms。此对照只隔离 Sheet
存储变化，**不是完整旧 checkpoint**。Paste 没有稳定收益，需继续处理；不能只报告 Undo。

## 第 3 步：相同散点样式的重复准备

profile 确认原生 SymbolAtlas 为每个同样式点重复构造缓存键。在既有
`ResponsivePlotDataItem` 中包装其现有 atlas：只有所有样式元组相等时查一次同一符号，
重复使用相同矩形；混合样式和其余原生行为仍委托原 atlas。没有删除、抽样或合并量测点。

新红测试先复现 1024 个相同点生成 1024 个键；修复后 1 个键。均一样式、混合样式、
样式变化和清理 atlas 的原生像素哈希全部相同，相关绘图/来源/方向专项 25/25 通过。
12×10k 点、5 轮交替 `setData` 的局部 P50 从 246.51ms 降到 148.71ms；不包含实际绘制。
完整原生单次 V/Z/Y 仍为 3289.88/2389.11/2681.74ms，300ms 验收失败。
接下来主要断点是密集更新仍经过子表完整识别/恢复与完整拟合准备，不把小范围样式收益
描述为整链达标。

## 密集版本增量提交实验：已撤回

在以上 3 步之后，另试过按父/子版本身份、原始行、表头、元数据与数值列资格作严格证明，
让全部 50 列变化也不重置子表。37 项既有/新增专项以及含 NA 缺口、非绘图 Tab 上的
完整 V/Z/Y 双页刷新专项通过；减少了 GUI 提交，但后台逐列资格验证增加成本。

同机 3 轮交替完整原生对照（10k×50、100 wafers、1225 对、实际当前图 repaint）P50：

| 操作 | 完整加载对照 | 版本增量实验 |
| --- | ---: | ---: |
| V | 3248.46ms | 3217.70ms |
| Z | 2315.11ms | 2326.45ms |
| Y | 2628.14ms | 2619.95ms |

每次原始点、字符串及全部拟合断言通过，每次 V/Z/Y 的 300ms 门槛都失败。
Qt 最大停顿中位数 V/Z/Y 从 1025/770/939ms 降为 874/611/799ms，
但完整时延没有可重复的实质收益。仅 3 次样本，不宣称稳定 P95。
另一个纯表格准备/提交交替对照甚至从 160.38ms 增到 195.08ms（排除分析/绘图）。

按“不保留没有收益的额外复杂度”约定，已撤回这次**未提交**的实验源码和对应新路径测试，
未回退分支、既有 3 个有效步骤或用户文件。完整补丁存于 QA 的
`data-version/withdrawn-dense-version-values.patch`；6 份原生样本与
`dense-paired-summary.json` 保留。不把这些已撤回实验的测试当作当前源码验收结果。
审查时发现的防护单独保留：版本采用不能遗漏字典中的额外外部单元格，新增回归验证。
下一步继续分析共同有效行的批量拟合；源码稳定后才跑本阶段一次完整隔离回归。

## 第 4 个保留步骤：共同有效行的批量拟合

对至少 8 个参数、至少 128 条同一有限观测，先证明各参数选中了相同 measurement sets，
严格保留原行序和重复位置，再一次计算居中协方差矩阵。均值/尺度保护沿用既有守卫，
R² 仍用原定义的逐点残差和居中总平方和，全部 predicted 数组立即产生，不延后到查看时。
NaN、不同参数的不同选择、常量、病态和小样本保留原路径。Reference、Raw 和跨表不混合。
这些统计量仅为调用局部对象，不附着在 Undo 版本或无限增长的缓存上。

修改前同一 10k×50 拟合基准 5 轮 P50 310.37ms（另 3 轮门槛红灯 306.62ms），
修改后 5 轮 P50 245.35ms。纯数据与 Correlation UI 相关 76/76 通过，覆盖独立居中 SVD、
尺度、NaN、选择、重复/逆序行、来源配对、常量与旧求解器回退。单次完整原生
V/Z/Y 仍为 3073.85/2196.78/2532.79ms，全部 1225 对与当前图数据验收通过，300ms 失败。
这个整链单样本不能称作稳定提速或封版通过。尚未运行本阶段完整回归。
