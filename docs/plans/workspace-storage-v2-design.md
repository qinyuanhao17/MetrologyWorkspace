# 完整方案：文档归属、分类后缀与独立分析副本

> 状态：Implemented locally，已按用户授权实施，未同步 GitHub。
>
> 日期：2026-10-03。本文基于本地已实现的统一 SQLite 工作区存储，细化文件后缀、
> 保存范围、子窗口菜单、独立副本与恢复语义。设计阶段仅编写文档；后经用户授权实施。
> 分类后缀与恢复协议已接入，正常容器格式不变；不提交或同步 GitHub。
>
> 本文的“v2”是方案版本，不代表 SQLite 容器的 `format_version=2`。
> 已实现的基线及历史验证记录见 [统一 WKB 存储方案](unified-wkb-workspace-storage.md)。

## 1. 决策简述

采用“一个所属文档、一个正式文件；独立工具各自成文档；导出副本不改变原归属”。

1. Match Workbook 继续使用 `.wkb`，包含父数据与 Preview/Final 的三个分析工具。
2. 独立 Wafer Map / Radius 使用 `.wmap`；Dynamic 使用 `.wdyn`；Correlation and Trend 使用 `.wct`。
3. 四种文件内部仍共用 SQLite / JSON / 表格存储，不引入 ORM、ZIP 外壳、pickle 或新的依赖。
4. 子窗口保存接受当前分析草稿，并写所属 Match 文件；其他子窗口的草稿不顺便接受。
5. 父窗口保存接受所有打开子窗口的草稿，一次写完整 Match 文件。
6. 子窗口不再提供整本 Match 的 Save As，也不保留隐藏的 `Ctrl+Shift+S` 路由。
7. 子窗口提供 Export Standalone Copy；副本包含当前实际数据及设置，之后独立编辑。
8. 修改过的父窗口、子窗口、独立工具关闭时都需要保存 / 放弃 / 取消；失败不能关闭。
9. 正式保存、草稿恢复、图片导出、数据导出是不同操作，不能互相清除未保存标记。

这里保留按窗口确认草稿的能力，不采用“在任何子窗口按 Ctrl+S 就接受所有分析修改”。
保存范围必须在菜单、固定归属信息和关闭提示中表达，不能只靠用户记住规则。

## 3. 文件类型与打开规则

### 3.1 正式后缀

| 文档 | 后缀 | 内部 `workspace_type` | 文件内容 |
| --- | --- | --- | --- |
| Match Workbook | `.wkb` | `match_workbook` | 父表、映射、公共设置、六个阶段分析作用域 |
| Wafer Map / Radius | `.wmap` | `wafer_map` | 完整输入表、Map 与 Radius 的选择和配置 |
| Dynamic | `.wdyn` | `dynamic` | 完整输入表、重复性及趋势配置、各参数 Die 选择 |
| Correlation and Trend | `.wct` | `correlation_trend` | Ref/Raw 两张表、独立选择、Correlation 与 Trend 配置 |

副本与独立工具使用相同的文件格式，副本不是仅能查看的报告。
备份在完整正式文件名后附加 `.bak`，例如 `晶圆分布.wmap.bak`。
短暂写锁同样附加 `.lock`，例如 `项目A.wkb.lock`，不作为需分享的文档附件。

### 3.2 内部类型是权威

- 后缀帮助文件选择和用户识别，内部 `workspace_type` 决定真实文档类型。
- 主窗口的 Open / 拖放 / 最近文件入口识别四种后缀，校验文件后再路由正确工具。
- 某个工具的 Open 不得把其他类型部分载入；可提示用户从主窗口打开对应工具。
- 新后缀与内部类型冲突时，明确显示两者。主窗口可经确认按真实类型打开，
  标记需规范另存；不能静默按后缀解释内容，也不能原位重写成另一种类型。
- 未知类型、损坏容器、不支持的容器或状态版本拒绝载入，不改变已有窗口数据。
- 缺少 `workspace_manifest` 只触发受控的旧 Match 格式识别，不把任意 SQLite 库当 Match。
- 打开只读取文件，不隐式迁移、改名、创建不存在的文件或修改其内容。

### 3.3 文件选择与路径规范

- Save 对话框只有当前类型对应的正式后缀；Open 提供四种工作区及 CSV/XLSX 导入过滤。
- 未输入后缀时补充正确后缀；识别大小写时不区分 `.WMAP` 与 `.wmap`。
- 输入其他已知工具后缀时提示改正，不允许在 `.wdyn` 中写 Map 内容。
- 旧独立 `.wkb` 转新后缀时必须显式选择路径，不能后台自动重命名或删除原文件。
- 文件名中的其他点号不应被误删；路径规范和覆盖确认须针对最终实际写入路径。
- 用户确认覆盖后记录目标当前 revision；在写锁内检测目标是否又被修改。
- 覆盖已有工作区还须校验其真实类型。错误类型或损坏的既有目标要求另选文件，
  不能因为后缀相同就直接覆盖。
- 导出副本不得覆盖所属 Match、当前独立文档、其备份/恢复草稿，或应用已打开的其他文档。
  比较解析后的路径，并在目标存在时检测同一文件的链接/大小写别名，不能只比较字符串。

## 4. 文档归属与分析作用域

```text
项目A.wkb：Match 文档
├─ match / match_ui：父数据、参数映射、公共分析设置
├─ map.preview：Preview Wafer Map / Radius
├─ map.final：Final Wafer Map / Radius
├─ dynamic.preview：Preview Dynamic
├─ dynamic.final：Final Dynamic
├─ correlation.preview：Preview Correlation and Trend
└─ correlation.final：Final Correlation and Trend

独立文件，互不关联
├─ 晶圆分布.wmap
├─ 重复性分析.wdyn
└─ 相关性趋势.wct
```

- 子窗口没有自己的正式保存路径，所有正式写入通过所属 Match 文档处理。
- 同一 Match 的每个作用域最多一个可编辑窗口；重复打开只激活已有窗口。
  激活不能静默覆盖窗口中的未保存数据、选择或正在输入的单元格。
- Preview/Final 的数据覆盖和局部选择分别保存，不混用。
- Match Type、Bias 及共享第二 Y 轴设置属于 Match 公共设置。
  第二 Y 轴模式与小数阈值仍适用于 Preview 和 Final，不能两边各保存一份可互相回滚的值。
- 不同 Match 文件及独立工具的设置互不影响。全局设置只作为新文档的默认值。

## 5. 数据与设置保存清单

### 5.1 表格

- 保留全部原始列，不只保存勾选参数或已画图的列。
- 保留行列顺序、ID、精确测量字符串、Unicode、空值语义。
  `001`、`2.1000`、`NA` 不能被存储过程擅自改写。
- 可保存重复表头、只有表头、空白内行、尚未完成映射等编辑草稿。
  容器可保存不等于数据可分析；分析仍执行既有校验。
- 保存有效逻辑表格范围，不保存电子表格中纯粹用于填充界面的无限空白网格。
- CSV/XLSX 原路径只可作为来源说明，重开分析不能依赖原文件仍存在。

### 5.2 局部配置

| 工具 | 必须保存的内容 |
| --- | --- |
| 所有工具 | wafer/parameter/grouping 勾选、Card 系数和开关、页签、布局、字体、分辨率 |
| Map / Radius | 两页实际框选、Draw 状态、X/Y、直径、色图、色阶、透明度、点/数值/轮廓/边缘/共享色阶/标尺 |
| Dynamic | 表格、绘图选择、趋势选项、各参数选定 Die |
| Correlation | Ref/Raw 各自选择、拟合框选、最小 R²、列数、分页大小与当前页 |
| Trend | 源身份、Add Compare 列表、Select maps、Draw 状态、布局与有效轴设置 |
| Match | Ref/Raw 和阶段数据、参数映射、顺序、Match Type、Bias、公共轴策略、Setup 布局 |

Add Compare 引用来自实际 Ref/Raw 数据，不通过所在图的标题推断。
相同参数名出现在两份数据时，仍是不同来源，保存后不能合并或互换。

### 5.3 不保存的内容

不存 Qt/Matplotlib/PyQtGraph 对象、pickle、截图缓存、可重算的拟合数组、Undo/Redo 历史、
临时搜索词、悬停状态和鼠标平移缩放位置。主题、语言及最近文件属于应用设置。

重开后从数据和设置生成图。已确认的 Draw 状态恢复；尚未确认的新框选仍待 Draw selected。
保存、导出副本和恢复都不能擅自替用户点击 Draw selected。

### 5.4 父源表与子表关系

- 未独立编辑的子表沿用现有阶段生成逻辑，在 Match 内可复用父数据而不重复保存。
- 子表被编辑或单独导入后，保存完整作用域覆盖；不再由父表重新生成覆盖它。
- Correlation 子表覆盖必须同时正确记录 Ref/Raw；独立副本始终物化两张实际表。
- 子窗口保存不能把其过时表格反向写回父 Raw 表、恢复父已删除的行或改变原匹配身份。
- 父源表变化时，未编辑的数据可以刷新；有独立数据修改的草稿保留为独立覆盖，
  显示“使用独立编辑的数据，与当前 Workbook 源数据不同”。
- 来源是否变化按表格/映射的实际版本判定，而不是按已绘图数量判定。
  重新使用父数据必须显式确认放弃独立数据修改；本期不自动合并测量表。
- 参数增减后的全选、框选后等待 Draw、仅数据更新时自动刷新，继续遵循既有绘图规则。

## 6. 菜单、快捷键与反馈

### 6.1 Match 父窗口

| 菜单 | 快捷键 | 明确行为 |
| --- | --- | --- |
| Open Workbook… | Ctrl+O | 打开 Match `.wkb`，先处理当前未保存修改 |
| Save Workbook | Ctrl+S | 保存父当前数据/公共设置及全部打开子草稿 |
| Save Workbook As… | Ctrl+Shift+S | 完整 Match 另存，成功后全体子窗口所属路径一起切换 |
| Recover Workbook Draft… | 不新增默认快捷键 | 恢复整个 Match 的基准和未保存草稿 |
| Reveal Workbook in Folder | 不变 | 定位当前正式文件，不定位恢复缓存 |

父窗口的 Save 工具提示明确写“包含所有打开分析窗口的未保存修改”。
本期不新增整个应用 Save All，也不替其他独立文件保存。

### 6.2 Match 子窗口

| 菜单 | 快捷键 | 明确行为 |
| --- | --- | --- |
| Save Changes to Workbook | Ctrl+S | 接受本分析草稿，同时保存父当前数据和公共设置 |
| Export Standalone Copy… | 本期不新增默认快捷键 | 将当前实际分析快照复制成对应独立文件 |
| Show Match Workbook | 无 | 激活所属父窗口，方便整本另存和恢复 |
| Export Data / Export Image | 既有导出入口 | 导出数据或图片，不改变文档保存状态 |

删除 Save WKB As 及其 `Ctrl+Shift+S` 委托。父快捷键使用窗口级作用域，不能因子窗口有
父关系就悄悄响应子窗口中的同一快捷键。也不把该快捷键偷偷改成导出副本。

子窗口不提供独立 Recover draft：恢复操作属于所属 Match，避免把其草稿恢复成脱离父关系的工具。

子 Save 的说明必须如实表达：

> 保存当前分析到项目A.wkb，同时保存 Workbook 当前数据和公共设置。
> 其他分析窗口未保存的修改不会包含。

### 6.3 独立工具

使用 Open / Open Recent / Save / Save As / Recover Draft；Open 为 Ctrl+O，保存和另存为为
Ctrl+S、Ctrl+Shift+S。Open 复用数据区原有打开动作，避免重复快捷键冲突。
Open Recent 复用持久化最近文件，仅显示本工具内部类型兼容的正式文档，包括旧工具 `.wkb`；
过滤缺失、损坏及恢复草稿，空记录提供禁用占位。打开和最近打开均先处理未保存修改，取消则保持原文档。
该文档打开菜单用于主窗口启动的独立工具；Match 子工具的数据导入仍保留原所属工作簿。
对话框显示工具名称和对应后缀，不再统一显示 Save WKB。
CSV/XLSX 导入是文档修改，第一次 Save 仍需选择正式工作区路径；Export CSV 不是 Save。

### 6.4 可见归属

- 父标题：`项目A.wkb — Match Workbook *`。
- 子标题：`Preview Wafer Map / Radius — 项目A.wkb *`。
- 独立标题：`晶圆分布.wmap — Wafer Map / Radius *`。
- `*` 表示尚未正式保存的相关修改，不表示仅仅“还有图没画”。
- 子窗口固定信息：`保存到：项目A.wkb · Preview / Wafer Map`，完整路径可在提示中查看。
- 尚无正式文件时显示“未保存的 Match Workbook”，不显示伪造的已保存路径。
- 父标题/状态综合父自身及所有子草稿：子 Save 后仍有其他草稿，父仍显示未保存。
- 保存成功显示目标和范围；导出成功显示“已导出独立副本，原 Workbook 保存状态未改变”。

## 7. 保存范围与事务

### 7.1 状态术语

| 状态 | 含义 |
| --- | --- |
| 正式基准 / accepted | 最近成功正式保存的内容；新文档使用会话起始基准，但不能称已落盘 |
| 父当前状态 | 父表格及公共设置正在编辑的值 |
| 子草稿 / draft | 子窗口相对其基准尚未接受的表格和局部配置 |
| dirty | 数据或可持久化配置与基准不同，或导入/恢复后尚未正式保存 |
| pending draw | 框选变了但尚未确认绘制，与 dirty 和已落盘是不同概念 |

父文档有任一子草稿即存在未保存修改。公共设置属于父，不能纳入其他子窗口的局部放弃。

### 7.2 子 Save

1. 提交当前单元格编辑器与 spinbox 文本，采集数据模型及设置；不要求重新画图。
2. 纯构建候选快照：父当前数据/公共设置、本分析当前草稿、其他分析的 accepted 状态。
3. 获取/确认所属 Match 正式路径，执行一次完整文件原子保存。
4. 写盘成功后，才更新父路径/revision、父已保存字段和当前分析基准。
5. 其他子草稿和基准不变；父仍有未保存子修改时刷新而不是删除恢复草稿。

成功后提交的基准必须对应真正写入的候选快照，不是随手重采集的最新 UI。
若保存期间又产生编辑，新编辑留在窗口且仍 dirty；公共设置的正式基准只更新父级权威状态。

“局部保存”指接受哪一份草稿，不是对 SQLite 文件仅覆盖几个字节。
父源数据和公共设置也会落盘，不能宣传成只写本窗口。

### 7.3 父 Save / Save As

构建父当前状态加全部打开子草稿的一份候选快照，写盘成功后一起更新基准。
未打开的作用域保留已有 accepted 状态，不因未打开而被清空。
Save As 成功才改变正式路径；旧文件保留，全部子窗口归属信息同步更新。

### 7.4 失败和取消

取消路径选择、磁盘不足、写锁、revision 冲突、备份失败或最终替换失败时：

- 正式基准、正式路径、revision 与未保存草稿保持不变。
- 不关闭窗口，不标记 clean，不清空 Undo，不删除恢复草稿。
- 不把提前修改 accepted 再尝试写盘作为正常流程；若现有实现暂时采用快照回滚，
  必须覆盖所有接受状态、路径及基准，并用故障测试证明等价。
- 原子替换成功但辅助 UI/最近文件/恢复清理失败时，应报告“文档已保存，辅助操作失败”，
  不能声称正式文件未保存或恢复到过期基准。
- 替换后的写锁删除、revision 获取、基准显示更新失败也须区分已提交事实；
  保存流程保留候选快照和提交结果，不以一个清理异常回滚到旧 accepted。

### 7.5 具体例子

正式文件里 Map 是 M0、Dynamic 是 D0。两个窗口分别修改到 M1、D1。

- 保存 Map：文件成为 M1 + D0；Dynamic 的 D1 仍在窗口中、仍未保存。
- 然后放弃 Dynamic：重开得到 D0，Map 的 M1 不受影响。
- 若从父窗口保存：文件成为 M1 + D1，两者都更新基准。
- 已正式保存的 M1 不是后来一次 Discard 的对象；要回退正式保存需恢复上一版备份。

公共第二 Y 轴只有父级权威值。放弃 Final 的局部选择，不能把已保存的公共轴阈值回滚。

## 8. 关闭、替换与应用退出

| 请求 | Save | Discard | Cancel |
| --- | --- | --- | --- |
| 关闭有修改的子窗口 | 按第 7.2 节保存，成功才关闭当前子窗口 | 放弃当前局部草稿，不改父表/公共设置/其他子 | 当前窗口及编辑保留 |
| 关闭有修改的 Match | 按第 7.3 节一次保存，成功后关闭父及子 | 放弃父和全部子未保存修改，一起关闭 | 父和全部子保留 |
| 关闭有修改的独立工具 | 保存本工具完整文档，成功才关闭 | 放弃本工具未保存修改 | 本工具保留 |

无修改直接关闭。无正式路径时 Save 必须选择路径；取消选择等于取消关闭。
父关闭已做总体决定，不再逐个弹同一 Match 的子窗口提示。

子窗口关闭提示显示当前分析和所属文件，并说明 Save 同时包含父当前数据/公共设置。
若只是父公共设置变动而子局部无修改，子直接关闭，父仍保持 dirty 并负责提示。
子 Discard 后重新生成未覆盖的派生表可使用父当前源数据，但不能改变任何父测量值。

导入新表、Open 替换当前文档、重新生成将覆盖编辑数据等动作，复用同样的决策规则。

主程序退出按所属文档处理，不能将 Match 子窗口当成独立文档重复询问。
推荐先收集关闭决定再写盘，未完成决定前不销毁窗口；Cancel 停止本次退出。
各正式文件独立提交：若较早的文件保存成功而后一个失败，保留所有窗口并明确哪些已保存，
不能承诺多个独立文件之间存在统一数据库事务或把成功保存伪装成被撤回。
收集到 Discard 只暂存决定；全部必要保存成功、确认可以退出后才丢弃对应编辑并清理草稿。
后续 Cancel 或保存失败时，这些尚未执行的 Discard 不得提前清掉其他文档的修改。

## 9. 独立副本的完整语义

### 9.1 导出范围

导出的是本工具当前实际数据及配置，不是整本 Match，不是几张选中的图。

| 当前窗口 | 独立副本的表 | 独立副本状态 |
| --- | --- | --- |
| Wafer Map / Radius | `input_data`，包含全部列 | `ui`，同时包含 Map 与 Radius |
| Dynamic | `input_data`，包含全部列 | `ui`，包括各参数的选定 Die |
| Correlation and Trend | `reference_data`、`raw_data` | `ui`，包括来源选择、分页和 Add Compare |

- 从当前子窗口的 `workspace_snapshot()` 生成，不重新从父源表计算。
- 物化实际表，副本移动到其他目录或机器后仍可打开。
- 将继承的公共第二 Y 轴模式/阈值及实际使用的 Card 系数复制成独立设置。
- 不携带父保存路径、管理回调、其他阶段/其他工具、恢复文件路径或原文件 revision。
- 保存草稿也被复制：未 Draw 的框选仍未 Draw；无效测量草稿仍可编辑，不能强制分析成功。

### 9.2 对原文档的影响

导出也须先提交当前单元格和 spinbox 输入，之后采集纯快照，不触发接受草稿的回调。
这次输入进入模型可以正常产生 dirty；“导出不改变 dirty”指不能因为导出成功而清除未保存修改。
导出成功不修改父/子的 accepted、正式路径或所有权；原文件不被修改。
导出成功后提供“打开副本”可选入口，默认不自动打开，不把原窗口切换成独立工具。
打开副本后其配置和测量修改不回写原 Match；没有双向同步和隐藏文件链接。

副本文件本身是完整的正式文档；“原窗口仍 dirty”不代表副本没有保存成功。
导出失败或取消只报告导出结果，原草稿保持可继续保存或放弃。

默认名称可用 `项目A-preview-wafermap.wmap`、`项目A-final-dynamic.wdyn`、
`项目A-preview-correlation-trend.wct`，用户可更名，不以名称判断内容。

## 10. SQLite 最终结构

继续使用已有四类公共表，不因后缀差异另建数据库实现：

| 表 | 职责 |
| --- | --- |
| `workspace_manifest` | 容器版本、真实工具类型、保存时间 |
| `workspace_state` | 作用域、状态版本、JSON 配置 |
| `frame_catalog` | 逻辑表名、内部 SQL 表名、原表头、dtype、行数 |
| `frame_0` 等 | `row_order` 与内部 `c0` 等测量列，保留完整行序 |

Match 的 `parameter_mappings` 继续作为从同一权威映射快照生成的 SQL 检查视图性质的关系表，
恢复时以同一份权威状态为准；不能让 JSON 与关系表各自独立编辑。

保持 `format_version=1`、正常作用域 `state_version=1`。
改变后缀、菜单、路径处理不构成容器结构升级。以后必需结构有不兼容变化时才升版本。
第 12 节的新恢复作用域单独使用 `state_version=2`；旧读取器会明确拒绝这种恢复文件，
而不是误把分层草稿当成普通文档。四种正式文件不携带这一作用域，正常存储版本不变。

逻辑表名允许保留来源/阶段身份；SQL 表列仍使用内部生成标识和参数化值。
不执行外来 SQL、不启用 SQLite 扩展、不加载可执行 Python 对象。
可选来源说明不参与分析，也不作为缺少源 CSV 时禁止打开的条件。

## 11. 安全写盘、备份与冲突

一次正式保存遵循：

1. 校验最终路径、文档类型、覆盖权限和受保护同文件限制。
   普通 Save 允许覆盖自己的正式路径；副本导出及跨文档目标不能借此覆盖所属原件或其他已打开文档。
2. 获取短暂写锁，检查用户打开/确认覆盖时的文件 revision。
3. 在同目录临时文件中写完整 SQLite 快照，提交、关闭连接、校验并同步。
4. 保留上一份正式文件为 `完整文件名.bak`；备份失败时不继续替换正式文件。
5. 临近最终替换再核对 revision，防止准备快照期间目标发生变化。
6. 原子替换成功后更新文档状态，再做最近文件和恢复清理等辅助操作。

保存失败保留原文件。备份是一份上一版，不是无限撤销历史；恢复备份先复制为新的规范后缀文件。
正式文件不需要另带运行时 WAL/SHM 才能恢复分析；分享时提供完整且已关闭写入的正式文件。

同一文件被两个窗口打开允许查看，但后保存者必须通过 revision 检查；不自动合并。
有锁时显示目标和处理建议；崩溃残留锁只有确认所有实例停止写入后才能清理。
不自动删除任意其他实例的锁。

只读文件允许查看和内存编辑，保存时要求另存到可写路径，不偷偷覆盖权限受限原件。
不得宣称锁与 revision 能阻止不遵守协议的外部程序、云同步或设备故障产生的一切竞争。
OneDrive/网络目录允许用户选择，但不提供多人协作合并保证；重要分析优先本地正式保存后再复制分享。

## 12. 恢复草稿的归属与分层

### 12.1 谁负责恢复

- 每个独立文档有一份恢复草稿；每个 Match 有一份聚合恢复草稿。
- Match 子窗口不再额外创建会被误认为独立工具的恢复文档。
- 保留 30 秒周期；数据或配置修改不逐次写 SQLite、不为了草稿强制出图。
- 默认仍使用 `%LOCALAPPDATA%/MetrologyWorkspace/recovery/`，不写进用户选定的正式文件。
- 内部文件名可为 UUID 加真实类型后缀；匹配来源依据元数据，不依据 UUID 文件名猜测。

### 12.2 必须保留两层状态

恢复文件要保存正式基准、父当前数据/公共设置、各未接受子草稿，而不是只有最终画面。
否则恢复后无法实现“保存 Map，但放弃 Dynamic 恢复到原 D0”。

建议仍用同一个 SQLite 容器，增加恢复专用 JSON 元数据，不把 DataFrame 塞进 JSON：

- `workspace_state` 中 `scope=recovery` 的 `state_version=2`：旧读取器必须拒绝的版本门槛。
- `recovery.payload_version=2`：描述恢复协议，独立于正常容器版本，不能独自替代版本拒绝门槛。
- 原始正式路径与原文件 revision、会话标识、恢复时间。
- 正式基准的 frame/state 引用，未命名文档的会话起始基准。
- 父当前状态及每个草稿的 scope、实际 frame/state 引用、来源版本。
- 未接受作用域清单，用于恢复后正确显示 dirty。

表格仍放在 `frame_catalog` / `frame_*`。恢复角色与表格的对应关系放入 JSON。
相同表格可以引用同一逻辑表记录；发生修改时保存相应基准表和当前表。
恢复文件专用 frame/state 不能作为普通 accepted 分析作用域载入；正式保存时移除恢复元数据。
正式候选快照也要排除恢复专用基准/草稿 frame/state，只保留这份正式文档实际接受的内容。
新读取器专门解释恢复作用域版本 1/2，其他作用域仍按其支持的版本校验；未来恢复版本拒绝载入。
普通 Open 和 Recover 都先检测恢复标记、校验恢复版本并走恢复流程，不因外层容器版本为 1
就按正式文档的 clean 状态恢复分层草稿。
基准和草稿并存会增加空间成本，应测量，不声称免费保存两份数据。

### 12.3 清理规则

| 操作结果 | 恢复草稿处理 |
| --- | --- |
| 父保存成功，全部 clean | 删除所属恢复草稿 |
| 子保存成功，仍有其他草稿 | 立即刷新为新基准加剩余草稿，不能删除 |
| 子放弃，仍有其他修改 | 删掉本 scope 草稿并刷新聚合恢复 |
| 父/独立工具放弃关闭 | 清理所属恢复草稿 |
| Cancel、保存失败、导出副本 | 保留恢复能力；导出不会清除草稿 |

子 Save 成功后刷新恢复文件失败，不撤回已经成功的正式保存；保留旧恢复文件并警告
“剩余草稿恢复尚未更新”，不能假装当前恢复文件与新 revision 已完全一致。
恢复元数据中的旧 revision 让之后的过期写入被拒绝。

### 12.4 恢复打开与旧草稿

恢复时先处理当前文档未保存修改，再校验并载入基准与草稿；恢复后仍未保存。
恢复路径不是正式 Save 目标。原正式文件仍匹配记录 revision 才允许按原路径保存；
原件被修改则要求另存或重新打开最新文件，不能强行覆盖。

旧恢复文件没有分层基准时：若原正式文件存在且 revision 匹配，可只读获取基准。
若不能取得可靠基准，明确提示不能保证局部 Discard 的参照，要求先将整份恢复内容另存；
在此之前不提供可能错误的子局部保存/回退。不能从恢复画面猜一个所谓已保存基准。
这里的另存是继续局部保存的前提，不是强迫用户保存：仍可 Cancel 保留恢复会话，
也可明确放弃整份恢复会话并关闭；只有完整另存成功才建立新基准、恢复局部 Save/Discard。
新分层恢复文件不保证旧软件能读；恢复作用域版本门槛应让旧软件拒绝，而不是降级解释。

本期保留手动 Recover Draft，不新增启动时强制恢复弹窗。
首次周期前、操作系统拒写或设备损坏的修改不能保证恢复；草稿不替代正式 Save。

## 13. 旧文件兼容与迁移

| 旧文件 | 打开 | 下一次正式保存 |
| --- | --- | --- |
| Match schema 1–10 `.wkb` | 既有旧格式只读识别、恢复数据与状态 | 显式保存后写当前统一容器，保留上一版备份 |
| 统一容器 Match `.wkb` | 正常打开 | 继续保存 `.wkb` |
| 统一容器独立工具 `.wkb` | 依据内部类型打开，提示推荐后缀 | 即使已有路径，首次 Save 也要求另存规范后缀；旧文件保留 |
| 正确新后缀 | 按内部类型校验并打开 | 正常保存 |
| 后缀与内部类型不匹配 | 主窗口提示，经确认可按真实类型打开 | 必须另存到正确后缀，不原位更换内容类型 |
| 更高版本或损坏文件 | 明确拒绝，不部分载入 | 不允许降级或重写原件 |

迁移不删除源文件，不自动转换整个目录，不改测量值、行映射、列顺序和参数来源。
旧独立工具规范另存保留原文件及原字节；旧 Match 原位升级会替换该路径内容，旧版留在 `.bak`。
若希望旧 Match 原件字节也不变，使用父窗口 Save Workbook As 选择新路径。
取消迁移路径选择，仍保留当前文档与全部草稿，关闭时也不能绕过取消。
新版本读取旧文件不代表旧软件必定读取新工作区；对旧软件交换可用 CSV/XLSX，
但这种导出不携带完整工作区状态。

最近文件显示工具类型、文件名与路径；Match 菜单只列 Match，主窗口可列所有类型。
旧最近文件中的独立 `.wkb` 仍可打开。规范另存成功后加入新路径，原文件未删除时不伪称不存在。
最近文件更新失败不能影响保存结果，也不能重置用户主题等全局设置。

## 14. GitHub 借鉴与取舍

QGIS 将会话作为项目保存，项目文件包含视图与布局等状态，图像/PDF 生成另走输出操作。
借鉴的是保存归属，不照搬其对外部数据源路径的依赖。
[QGIS 官方项目文件文档](https://github.com/qgis/QGIS-Documentation/blob/master/docs/user_manual/introduction/project_files.rst)

FreeCAD 明确区分 Save、Save As、Save a Copy、Save All 与 Export。借鉴其“切换当前文档路径”
和“生成副本”是不同操作；本项目副本不改归属/dirty 的语义是这里的设计决策，
不声称它们已有完全相同的父子草稿模型。
[FreeCAD 官方命令定义](https://github.com/FreeCAD/FreeCAD/blob/main/src/Gui/CommandDoc.cpp)

| 备选 | 不采用的原因 |
| --- | --- |
| 所有正式文件继续 `.wkb` | 文件层面难以区分，不符合这次需求 |
| Match 内每个工具各存外部关联文件 | 移动和分享易缺附件，归属和关闭决策更复杂 |
| 子 Save As 悄悄另存整本 Match | 用户在 Map 中操作却改变整本路径，范围误解 |
| 子 Save As 自动脱离父文档 | 后续编辑突然不再写 Match，容易丢关联 |
| 任意子 Ctrl+S 接受全部其他草稿 | 破坏各窗口独立确认修改的预期 |
| Apply 进内存再 Save 落盘 | 增加操作层级，不符合子关闭时直接保存的需求 |
| 新建数据库框架或替换 SQLite | 类型/菜单问题不需要更换已存在的存储技术 |

## 15. 最小实施拆分

### 第一阶段：后缀和归属

- `workspace_store.py` 集中类型到后缀的映射、路径校验，取消全类型强制 `.wkb`。
- `workspace_document.py` 复用现有正式保存/失败保护，增加类型化路径选择和旧后缀规范另存。
- `window.py` 按托管/独立身份配置菜单；去掉子 Save As 路由；显示实际所属文件。
- `matching_window.py` 保留父/子不同接受范围和每 scope 单实例；更新公开反馈。
- `shell.py` 识别四种后缀，校验后按真实类型路由。

### 第二阶段：独立副本

复用子窗口 `workspace_snapshot()`，清除管理/恢复元数据、物化继承配置并通过同一个
`save_workspace()` 写出。原对象不得调用 `mark_clean()` 或修改其正式路径。
不为三个工具各写一套导出数据库代码，也不新增通用插件系统。

### 第三阶段：恢复、共享字段与事务补强

统一 Match 恢复归属，加入基准/草稿分层；子保存/放弃后保留剩余恢复能力。
公共轴策略只保留父级权威值；保存采用候选快照成功后提交，补最终 revision 复核。

### 第四阶段：兼容、文案与回归

扩展现有存储和窗口测试，检查文件选择、最近文件、只读目标、失败提示、真实快捷键路径。
BDD 示例连接到 Python unittest，不安装 Cucumber.js 或新增一套运行器。
测试使用隔离的 `METROLOGY_SETTINGS_PATH` / `METROLOGY_RECOVERY_DIR`，不能改用户配置。

容器格式、数据计算、绘图数值、单位识别、Undo 模型不随此方案重做。
正式文档的 Windows 文件关联、专用图标和双击启动可另行实现，不作为存储正确性的前提。
本方案不包含 GitHub 推送、打包新 EXE、云协作、自动同步副本或导入副本回写 Match。

| A17 | 写盘/备份/最终替换失败 | 原文件与 accepted 不变，所有有关草稿可继续保存或放弃 |

| A24 | 只读文件、清理草稿/最近文件失败 | 原件不被偷偷改写，辅助失败不误报正式保存失败 |
| A25 | 退出时一个文档选 Discard，后续另一个 Save 失败 | 尚未执行的 Discard 保留编辑/恢复；已保存文件如实更新基准 |
| A26 | 普通 Open 新恢复 v2/不支持的恢复 v3 | v2 专用分层恢复且仍 dirty；v3 拒绝，旧读取器拒绝 v2 |
| A27 | 旧恢复缺少可靠基准 | 可 Cancel 或整体放弃；整份另存成功后才启用局部保存/回退 |
| A28 | 未失焦的单元格导出副本 | 副本含刚输入值；原窗口保持未保存，路径和归属不变 |
| A29 | 候选快照写入期间又有新编辑 | 落盘值和基准对应候选，新编辑保留且仍 dirty |
| A30 | 文件已替换，但写锁删除或 revision/UI 更新失败 | 承认正式保存已提交，不回滚 accepted、不误报原文件未改 |

## 18. 用户使用示例

1. 在 Match 导入数据、完成匹配，从 Preview 打开 Wafer Map。
2. 调整晶圆图，按子窗口 Ctrl+S，保存到所属 `项目A.wkb`。
3. 需要把此分析给同事时，选择 Export Standalone Copy，生成 `项目A-preview-wafermap.wmap`。
4. 同事只拿这一份 `.wmap` 就能继续编辑，不需要原 CSV 或整本 Match。
5. 你的原窗口仍属于 `项目A.wkb`；导出后新产生的修改继续按所属 Match 保存。
6. 想连同其他子窗口一起保存或复制整个项目时，回到 Match 使用 Save Workbook / Save Workbook As。

一句话：Match 内保存归 Match，独立工具保存自己的文件，单独带走某个分析使用独立副本导出。
