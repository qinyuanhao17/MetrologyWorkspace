## Repeatable map-update comparison

Run `scripts/benchmark_die_map.py <SME-folder> --mode rebuild|incremental
--output <result.json>` with the application's Python environment. The script
isolates settings, settles initial layout, toggles the same source five times
and includes event processing and page painting in each measurement.

Using JC1913 (1,890 files, twelve displayed maps, 1600 × 1000), the full-page
replacement control had a **1,100 ms** median; incremental updates had a
**59.5 ms** median. Every control update replaced plot widgets; incremental
updates replaced none and kept all settled sizes. This measures Die Map
updates, not total spectrum-rendering or application-wide latency. Results:
`v5-dev-die-map-rebuild-2026-11-03.json` and
`v5-dev-die-map-incremental-2026-11-03.json`.
