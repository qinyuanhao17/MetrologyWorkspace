# 如何维护 Help / SOP

这个文件夹独立保存帮助目录、教程正文和截图。修改这里的文档不需要修改 Python 程序，也不会改变 WKB 或数据分析结果。文件统一保存为 **UTF-8**。

## 文件分工

| 位置 | 用途 |
| --- | --- |
| `toc.yaml` | 左侧树形目录：章节标题、顺序、层级、正文文件路径 |
| `pages/` | Markdown 格式的 SOP 正文 |
| `images/` | SOP 截图，建议使用 PNG 或 JPEG |
| `README.md` | 本维护说明，也可以通过 Help 左侧目录打开 |

## 修改已有教程

用文本编辑器、VS Code 或 agent 修改相应的 `.md` 文件并保存，然后在 Help 窗口点击 **Refresh**，或在该窗口按 **F5**。刷新会重读目录和当前页面，不需要重新启动程序。

帮助窗口用于阅读。编辑正文和目录请直接修改文件；**Open help folder** 可以打开当前正在使用的帮助文件夹。

## 增加、移动或删除章节

先在 `pages/` 下创建正文，再编辑 `toc.yaml`。例如：

```yaml
version: 1
home: pages/welcome.md
topics:
  - title: Match Workbook
    file: pages/match_workbook.md
    children:
      - title: 新增 SOP
        file: pages/new_sop.md
```

- `version` 保持为 `1`；`home` 指定首页。
- `topics` 是顶层章节列表；`children` 是子章节列表，可以继续嵌套。
- `title` 是目录显示名称；`file` 是相对于 **help 文件夹** 的正文路径。
- 同一层列表中，从上到下的顺序就是显示顺序。
- 只用作目录分组的节点可以省略 `file`，点击后展开子目录。
- 删除章节时，删除对应目录项即可；文件可以先保留备用。
- YAML 缩进使用空格，不使用 Tab。含特殊符号的标题建议用引号包围。
- 正文路径必须在这个帮助文件夹内。支持 `.md`、`.markdown`、`.mkd`，也可使用简单 `.html` 页面。

如果 YAML 格式有误或正文不存在，窗口会显示具体提示。修正后再次点击 **Refresh** 即可，程序不会自动改写你的文档。

## SOP 正文模板

将下方模板复制到新的 Markdown 文件，再填写内容：

```markdown
# SOP 标题

## 目的与适用范围

填写本操作的用途、适用模块及 Workbook 类型。

## 准备材料

- 所需文件、表头、参数或截图。

## 操作步骤

1. 第一步。
2. 第二步。
3. 第三步。

## 结果检查

填写预期结果和检查方法。

## 常见问题

填写问题现象与处理方法。
```

## 插入截图、表格和链接

例如图片放在 `help/images/example.png`，正文放在 `help/pages/example.md`，正文中写：

```markdown
![操作界面](../images/example.png)

[返回欢迎页](welcome.md)

| 参数 | 说明 |
| --- | --- |
| Wafer ID | 填写说明 |
```

目录中的 `file` 始终相对于 help 根目录；**正文中的图片和页面链接则相对于这篇正文所在目录**。目录名和文件名建议保持稳定，移动文件后同步修改引用。

Help 使用 Qt 原生文档查看器，适合标题、步骤、列表、普通表格、代码块及静态截图。复杂网页脚本、动态图表或网页级排版不适用于这个查看器。外部网页链接点击后会交给系统浏览器。

## 软件路径与主题

源码运行时读取项目根目录下的 `help/`，不依赖从哪个工作目录启动。可通过窗口的 **Open help folder** 确认实际路径。

将来打包时会附带这个文件夹；打包程序优先读取可执行文件旁的 `help/`，若没有则读取随包提供的帮助内容。维护时请修改窗口实际打开的文件夹。

帮助内容采用独立的普通文本和图片文件存放，不写入 WKB。Help 窗口随软件的 Light / Dark 主题切换。
